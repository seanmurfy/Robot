# Winslow robot project

Winslow is a DIY companion robot. Right now it is a single-page web app (`index.html`) that runs on a phone and acts as the robot's face and brain. Later it will run on a donor Android phone mounted as the head of a two-legged, wheel-footed balancing robot.

## Current state (Phase 1: phone brain, no hardware yet)
- One file: `index.html` (HTML + CSS + JS, no build step, no frameworks), plus the PWA files `manifest.json`, `sw.js` and `icons/`.
- Hosted on GitHub Pages from the `main` branch: https://seanmurfy.github.io/Robot/
- Winslow's permanent device is a Google Pixel 8 (Android Chrome), since November 2026. Earlier builds were tested on iPhone in Chrome (Safari speech recognition was blocked by iOS settings); the iPhone workarounds are still in the code.
- `models/vosk-model-small-en-us-0.15.tar.gz` (41 MB) is the wake-word speech model (see "Wake word").

## What index.html does
- **UI (face-first, section 9):** only the eyes and mouth show. An invisible full-screen `#tap` layer (z-index 1, under every control): tap = `toggleMic()` (start/stop talking, runs inside the tap handler for iPhone); swipe up or tap the bottom 15% = slim `#dock` (keyboard → `#typebar`, camera → live preview, settings). Dock auto-hides after 5 s and when listening, speaking or getting sleepy (`hideDock()`). The old `#mic`, `#look`, `#gear` buttons are kept hidden because the logic drives them. Winslow's spoken words appear at his mouth (`#speech` in `#mouthBox`, `body.saying` hides the mouth bar): `speak()` calls `sayStart()`, which shows one sentence-sized chunk at a time (`chunkText()`), lighting each word as it is said via `onboundary` word events, or a time estimate (~12 chars/s × rate) when the browser sends none; `sayEnd()` holds the last chunk 1.6 s; `mouthSay()` shows a line with no speech. The top caption is for the human's words and status messages only. Captions (`show()`) fade out 4 s (longer for long text) after listening/thinking/speaking stops; full text, no -webkit-line-clamp (garbles on iPhone). With the camera open, a photo is only sent for the first message, `LOOK_RE`/`VISUAL_RE` words, or Snap, to stop Winslow re-describing the same scene. Version + sleep timer live in settings; "Show debug info" (`brain.debug`) also shows them bottom-left. First-run hint once (`brain.hintShown`). Icons are inline SVG, 48px tap targets. z-index: tap 1, face 2 (59 while the dashboard is open), z's 5, captions/hint 6, timer ring 7, debug 10, preview 20, dock/typebar 30, dashboard 60, backup offer card 64, ringing-timer caption 65, drop hint 90, settings 100.
- **Face:** animated pale-blue eyes (`--eye`) that blink and make small, slow glances; the listening glow is orange (`--listen`) so it stays distinct. Expressions are deliberately subtle (happy = soft eyes with a lifted lower lid, excited = slight brightening + one small nod, surprised = a raised eyebrow); emotions `happy`, `excited`, `sad`, `surprised`, `thinking`, `sleepy`, `neutral` (plus internal `asleep`) set via `setMood()` as CSS classes on `<body>`.
- **Sound:** `chirp()` plays one soft, low sine tone (signature sound), only when the mood changes to excited, on waking and when greeting a newly seen face.
- **Voice out:** browser `speechSynthesis`; voice, pitch (default 0.9) and rate (default 1.0) are user-selectable in settings. "Automatic" voice prefers en-GB, then en-US. Voices load a moment after the page does, so `speak()` waits (up to 1.5 s, polling `getVoices()`) before the first line; otherwise the first sentence after a reload came out in the default voice.
- **Ears:** `webkitSpeechRecognition` (tap the face) plus a typed-text fallback (dock keyboard). Conversation mode (`brain.convo`, on by default): after one face tap, `continueConvo()` restarts listening each time Winslow finishes speaking a reply; sends after a 2 s pause in speech (own timer, not the browser's), ends after one silent round (6 s with no speech), a second face tap, or if the browser refuses a non-tap restart. Each listen is capped at 15 s, and the mic is released when the page is hidden/closed (`releaseMic()`).
- **Background sound (v5.8):** mic results go through `judgeHeard()` before `think()` (typed text never does). "Listening sensitivity" (`brain.sensitivity`: strict/normal/relaxed, `LISTEN_LEVELS`) sets the lowest accepted confidence (0 = not reported, common on iPhone, so it can't be judged on it), a "clarify" level and a minimum word count (shorter must match `SHORT_CMD_RE`). "Only listen when I'm in view" (`brain.faceGate`, on by default, only while Follow faces runs on its own stream, `faceGateOn()`): no face in 5 s = ignored. "Noisy room mode" (`brain.noisy`): only sentences containing the name or a near-miss (`findName()`, edit distance) count, and the name is stripped. Ignored sound is logged as `ignored` (faint caption with debug on); 3 ignored in a row end conversation mode. A low-confidence search or movement request (`riskyRequest()`) is confirmed first: "Did you say …?" (`pendingConfirm`, 45 s; yes/no answers bypass the word and name rules). The mic never opens until 300 ms after Winslow's voice stops (`speechEndedAt`, `AFTER_SPEECH_MS`); a tap mid-speech cuts him off first. Pause-to-send is 2 s. Listening line on the Status tab.
- **Wake word (section 16, v6.5):** "Wake word" setting (`brain.wakeWord`, off by default, device-only: not in backups or setup links). Saying the name does what a face tap does: wakes him if asleep (`wake(listen)`, wake line first), otherwise a soft tone, then `startListening(true)` with conversation mode. The rest of the sentence is not captured: say the name, wait for "Listening…", then speak. Vosk runs on the phone: `vosk-browser@0.0.8` from jsDelivr, loaded by `loadVoskLib()` with a Subresource Integrity hash (`VOSK_SRI`), and the official small English model served from this site (`WAKE_MODEL`, files byte-identical to alphacephei.com's zip, repacked as tar.gz; the library downloads it once and keeps it in IndexedDB, Emscripten IDBFS under `/vosk`). The library's only network request is that model download (checked by reading its worker code); no audio leaves the phone. `wakeOpen()`: `getUserMedia` audio (echo cancelling off: it makes his voice very quiet on the Pixel) → own `AudioContext` (`wakeCtx`) → ScriptProcessor → `wakeAudio()` → `KaldiRecognizer` with a grammar of the name, "hey <name>", "wake up", sound-alike decoys (`WAKE_DECOYS`: winston, window, wins, slow…) and "[unk]". Without the decoys "Winston" and "he wins slowly" were heard as the name; `wakeResult()` also rejects the name straight after a decoy other than "hey". Audio is skipped while he speaks, for 600 ms after, and while a timer rings; a silent room (RMS under `WAKE_QUIET_RMS` for 1.5 s) rests the model. The browser's speech recognition can't share the mic on Android, so `openMic()` calls `wakeRelease()` first and `wakeTick()` (every second) reopens the stream when `wakeWanted()` (setting on, page visible, the browser's recognition not in use). `wakeHeard()` ignores the name while he is listening, in conversation, thinking, speaking, waking, in settings, typing or a timer is ringing; 3 s cooldown. `wakeFailed()`: mic blocked or model failure turns the setting off with a caption; other errors retry every 10 s, up to 5 times. Status tab line "Wake word". A name the model doesn't know (not an English word or common name) will never trigger. Still needs one tap per launch before he can speak aloud. **False wakes (v6.6):** on the Pixel he woke at random to audio from a PC, even on Strict (the sensitivity setting did nothing for the wake word then, and the model's confidence is always 1 with a grammar). Now `wakeJudge()` decides by where the name sits in one stretch of sound (between pauses), per "Listening sensitivity" (`WAKE_LEVELS`): Strict = the name entirely alone ("hey"/"wake up" in front allowed), Normal = at the start with at most one word after, Relaxed = at most one word before and six after; plus a per-word duration window (about 0.3–1.2 s) and still never straight after a sound-alike. The grammar also carries about 400 everyday words (`WAKE_COMMON`) so ordinary talk has somewhere to go other than the name. So "Winslow, what time is it" in one breath does not wake him on Strict or Normal: say the name, pause, then speak. Test with synthesized video/news/gaming speech in two voices: 6 false wakes under the old rule, 0 on Strict and Normal, 3 on Relaxed; "Winslow", "Hey Winslow", "Wake up, Winslow" woke him at every level. Tested only on desktop Edge with synthesized speech; real-room results on the Pixel will differ.
- **Interruptions / barge-in (v6.6):** "Let me interrupt him" setting (`brain.bargeIn`, on by default, in backups; `bargeOn()`). **Tap:** a face tap while he speaks aloud stops him silently (`toggleMic()` → `cutSpeech()`, ends conversation mode, no listening); with the setting off a tap behaves as before. **Voice (needs Wake word on):** the wake-word stream now stays open during conversation mode too (`wakeWanted()` no longer checks `convo`; `continueConvo()` releases it 350 ms before the browser's recognition restarts), and `speak()` calls `wakeTick()`. While he speaks, `wakeAudio()` feeds everything to Vosk (`bargeMode`, flushed with `wakeFlush()` at the start and end of each line so his own voice never lingers) and `bargeCheck()` reads the partial results: his name or `BARGE_WORDS` (stop, cancel, wait) must hold for `BARGE_STABLE` updates running (strict 5, normal 3, relaxed 2, about 85 ms each; a final result counts at once); sound-alikes are in the grammar as decoys (`BARGE_DECOYS`). Rejected (logged as `ignored` with debug on) when: he is saying that word himself (`selfSaying()`: his own text around the spoken position `sayCi`, 70 chars back / 40 ahead with word events, 160 / 120 on the time estimate; `BARGE_ECHO` covers homophones like weight/wait), noisy room mode and it isn't the name, or "Only listen when I'm in view" and no face in 5 s. Not active while a timer rings (it has its own listen). `bargeIn()` → `cutSpeech()`, then it depends on the word. **"Stop" / "cancel" = drop the matter:** no interrupted note, `eraseExchange()` removes his answer and the question before it from `brain.history` (only if the line being spoken is the last assistant entry) and forgets any memories that reply added (`lastReplyMem`, set in `think()`), conversation mode ends and the browser's recognition is not started (the wake-word stream itself stays, so Android's mic dot remains). Timers already set, notes on screen and the activity log are not undone. **His name / "wait":** `wakeListen()` (the usual listening, as after a wake word), with the interrupted note. `cutSpeech()`: `speechSynthesis.cancel()`, runs the line's own `finish` (`speakFinish`), sets `cutAt` so a `speak()` queued within 60 ms is dropped (its `onDone` still runs), and stores `cutNote` when 12+ characters were left unsaid. `takeCutNote()` (5 min life) prefixes the next AI-bound user message in history with `[interrupted after: "…"; the rest of your last reply was not heard]`; the system prompt tells the model not to repeat what was heard and to continue only if asked. Echo cancellation is never requested (v6.7): in v6.6 it was on while the setting was on, and on the Pixel that switched the phone to call-style audio and made his voice very quiet. Without it his own voice is in the mic signal while he talks, so a spoken interruption has to carry over it; the tap always works. Logic tested in headless Edge (32 checks); the audio side is untested on the Pixel.
- **Automatic updates (v5.9):** `checkForUpdate()` fetches `version.json?t=…` (`cache: "no-store"`) 3 s after launch, on returning to the foreground (at most once a minute) and every 30 min. If it is newer (`verNewer()`), `updateWhenIdle()` waits until `updIdle()` (not listening, in conversation, thinking, capturing, speaking, waking, dreaming, making a remark, typing or in settings; add "moving" once there is a body) holds for two 2 s checks running, shows "One moment, sir. Tidying up." and `reloadTo()` saves and goes to `?v=<ver>&t=<ms>` (stripped from the address bar on load). localStorage and IndexedDB are untouched. Loop guard: `winslowUpdate` in localStorage records the target; if the page comes up still older, it's logged and launch/foreground checks don't reload for that version again, only the next 30-minute or manual check. Settings: running version, "Check for updates", "Reload now", last check time when debug is on. The service worker (`sw.js`, v6.2) is network-first and never handles `version.json`, so it doesn't interfere.
- **Brain:** `think(userText, image, file, opts)` calls OpenRouter (`https://openrouter.ai/api/v1/chat/completions`) when an API key is set. The model must reply with JSON: `{"say", "emotion", "remember": [{text, category, date}], "used": [memory ids], "action", "item", "dashboard_tab"}`; `doAction()` runs the action (`show_dashboard`, `backup`; timer actions, skill actions and `recall_file` are handled inside `think()`). Order of local commands in `think()`: pending "Did you say…?" / budget question, `timerCommand`, `diagCommand`, `thinkAgainCommand`, `briefCommand`, `listCommand`, `backupCommand`, `faceCommand`, `memoryCommand`, `dashCommand`, then the budget gate (`budgetGate()`), then the camera and the AI; with no key, `offlineSkill()` then `replyOffline()`. With a shared file the reply may also carry `"file_desc"`. An optional `"display": {"title", "text"}` (simple markdown) carries anything that doesn't work as speech (lists, steps, recipes, code, tables, numbers, links, >3 sentences): `say` is just the gist + "it's on screen", and the dashboard opens on its **Notes** tab. `displayFrom()` also catches a `say` that is plainly unspeakable (list/code/table markup or >450 chars) and moves it on screen. Notes are kept in `brain.notes` (last 20, with search links), rendered by `mdHtml()` (escaped first, safe subset) with a Copy button; history keeps a shortened copy so follow-ups work. `max_tokens` is 1000 for this. Requests send `usage: {include: true}` so OpenRouter reports each reply's cost. With no key, `localBrain()` answers with offline regex rules.
- **Current facts:** every request's system prompt carries the local date, weekday, time and timezone (`nowText()`), plus `brain.homeCity` ("Home town" setting, optional; the geocoded label once looked up) and "Your human is American: US customary units first". Weather is not searched: it comes from the weather skill (section 17), so `weather|forecast` are no longer in `MUST_SEARCH_RE`. "Web search" setting (`brain.webSearch`, on by default; needs a key) adds OpenRouter's server tool `tools: [{type: "openrouter:web_search", parameters: searchParams()}]` = `{engine, max_results: 3, max_uses: 1}` ("Search engine" setting `brain.searchEngine`: perplexity (default), auto, exa). One search per reply; only if it finds no sources does `think()` send one retry with a "rephrase" nudge, and if that is empty too Winslow says he couldn't confirm it (never answers from memory). The prompt asks for self-contained queries (names instead of "they"/"it", month and year for schedules). The last successful search (sources with excerpts, query, answer) is kept in memory for 10 minutes (`lastSearch`, `recentSearchText()`) and put in the prompt so follow-ups answer from it without searching. Search cost today (`usage.searches`, `usage.searchCost`) uses `usage.cost_details.server_tool_cost` if reported, else the engine's list price (`SEARCH_PRICE`), shown on the Status tab. (The `web` plugin and `:online` suffix are deprecated; don't use them.) Search runs inside OpenRouter in the same request. The prompt tells the model to search anything time-sensitive and never guess; with search off or failed it must say it can't confirm. If the tool request fails (not auth/credit/rate errors), `think()` retries once without tools using `systemPrompt(true)`, and sets `searchBroken` for the session when the model can't use tools. While a search may be running: thinking face + "Consulting the wires…" (at once for `TIMELY_RE` questions, else after 2.5 s). `searchInfo()` reads `url_citation` annotations and `usage.server_tool_use_details` defensively (the docs only show the Responses API); each search is logged as a `search` event with sources as `links`, shown as tappable links in the dashboard log, never spoken. `parseReply()` tries every balanced `{...}` until one has `say`; `cleanSay()` strips URLs, links, citation marks and markdown from speech; history stores only the clean reply. Questions matching `MUST_SEARCH_RE` (scores, weather, news, prices, opening hours, next game…) and phrased as a question (`ASKING_RE`) must be backed by a search: if the model answers without searching, `think()` asks once more insisting on a search; if still none ran (or search is off/unavailable), the answer is replaced with "I can't confirm that at present" (skipped while the 10-minute `lastSearch` cache is fresh). Every request's system prompt ends with an EYES line saying whether a photo is attached; with none, he must not describe the human or the room and should suggest "look at me". Before sending a photo, `modelSees()` checks OpenRouter's public model list (`input_modalities`, cached per visit; unknown models allowed) and, for a model that can't take images, Winslow says so instead of sending. Offline: date questions answered locally; scores, news, prices etc. get "I'm afraid I can't confirm that at present".
- **Vision:** 👁 button opens a live camera preview (`openPreview()`); a `LOOK_RE` phrase ("what do you see", "look at this", "what do I look like", "how do I look", "what am I wearing") opens it too and snaps after a 1.5 s pause to aim the camera (v6.3, `SNAP_DELAY_MS`, caption "Hold it there, sir…"; no photo if the preview is closed meanwhile). Any photo asked for by voice or typing waits this long; a tap on the bubble (`snapNow`) snaps at once. While open, anything said or typed goes to `think()` with the current frame (`grabFrame()`: max 512px, JPEG q0.7, sent as an `image_url` part); The preview is a "daydream" thought bubble in the top right, 16px inside the safe areas (`#pvBubble` > `#pvClip` blob shape with feathered edges, slow morph and drift, `#pvTail` dots trailing toward the face; size `--pvw`). The picture itself is the shutter: tapping `#pvClip` (`snapFromBubble()`) sends "What do you see?" with a ring pulse (`#pvRing`) and a small dip (`#preview.snap`); while any photo is being sent, `#preview.sending` dims it and taps are ignored until the reply. The thought-trail dots below its lower-left are the controls (siblings of the shutter, so they never snap; round 48px tap targets ~50px apart, faint engraved marks): biggest dot ✕ `#pvClose`, middle dot flip `#flip` (when `enumerateDevices()` finds only one camera, `updateFlipDot()` → `setSolo(true)` makes it a plain, disabled dot), smallest dot decorative. Closing plays `#preview.closing` (the bubble shrinks back into the trail) before hiding. A faint "Tap to snap" shows under it for the first three opens (`brain.snapHints`). The eyes glance up-right at it (`lookAt(6, -5)`); in portrait the face re-centres below the bubble, in landscape to its left, and the top caption moves left of it. Camera choice is `brain.camera` ("user"/"environment"), set in settings or with the flip dot, falling back to any camera if the chosen one is missing. ✕, 60 s of no activity, or hiding the page closes the preview and stops all tracks. Needs an API key and a vision-capable model. Images are never stored; history gets a text note "[showed Winslow a photo]".
- **Installable app (PWA, v6.2):** `manifest.json` (name/short_name "Winslow", `start_url`/`scope` "./", `display: fullscreen`, `orientation: landscape`, background and theme colour `#05090c` = `--bg`) is linked in `<head>` with the theme-color meta, a 192 px icon and an apple-touch-icon. Icons in `icons/` (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png` with the eyes inside the 80% safe zone, `apple-touch-icon.png` 180 px): a dark circle with two amber pill eyes and a soft glow (amber, unlike the pale-blue face; generated with System.Drawing, not kept in the repo). `sw.js` exists only so Chrome offers "Install app": network-first for same-origin GETs (fetched with `cache: "no-store"`; pages cached under one "./" key so `?v=&t=` reload URLs don't pile up; the cache `winslow-v1` is only an offline fallback), never touches `version.json`, anything under `/models/` (the wake-word model), non-GET or cross-origin requests (OpenRouter, MediaPipe, CDNs). Registered on load over https or localhost. Wake lock: `keepScreenOn()` is also called at launch (plus every tap and on returning to the foreground), so the screen stays on while Winslow is open.
- **Sleep cycle:** after `brain.sleepAfter` idle minutes (setting: Never/2/5/10, default 2) Winslow yawns and goes `sleepy`; 3 minutes later `asleep` (breathing line eyes, floating z's in a `pointer-events: none` layer). Never sleeps while listening, thinking, speaking, settings open, or camera preview open. Any tap/key wakes him (`wake()`), unhurried: half-open sleepy eyes, then they open smoothly (`body.waking` slow transitions) with a soft tone, then a composed wake line ("Ah. You're back, sir."). The waking tap is swallowed so it doesn't also press a button; a typed message sent while asleep is answered after the wake line.
- **Face tracking (section 8):** "Follow faces" setting (`brain.followFaces`, off by default, not carried by backups or setup links). MediaPipe Tasks Vision `FaceDetector` (BlazeFace short range, VIDEO mode) from jsDelivr `@mediapipe/tasks-vision@0.10.14`, model from Google's mediapipe-models bucket. Hidden 640x480 front-camera stream (was 320x240 before v6.4; known faces need the detail), ~10 detections/s; when the live preview is open it detects on the preview's video instead (only one stream ever: `startCamera()` stops the tracking stream, `closePreview()` restarts it). Eyes glide (20%/frame) toward the biggest face, x mirrored, clamped to the glance range; eyes keep looking at the preview while it's open. New face after 10+ s → happy look, soft tone + "Good evening, sir." caption by time of day (no speech; with known faces the greeting waits up to 4 s for a name, see "Known faces"). No face for 30 s → random glancing again. Faces count as activity (`poke()`); while sleepy/asleep the eyes don't follow and detection slows to 1/s just to wake Winslow when a face appears. Paused while the tab is hidden and during snapshots. Model or camera failure turns the setting off with a caption.
- **Known faces (section 15, v6.4):** tells people apart. `@vladmandic/face-api@1.7.15` from jsDelivr (`dist/face-api.esm.js` with its own TensorFlow.js, plus tiny face detector, tiny 68-point landmarks and the recognition net from `/model`; about 8 MB, loaded by `loadRecog()` only once someone has been introduced, or on first use). MediaPipe still does the tracking; `trackTick()` records the biggest face as `lastSeenFace` `{box, src, at}`, and `faceprint()` cuts it out (`cropFace()`, a square 1.9x the box, 160–320 px) and returns a 128-number "face print". `matchFace()` = nearest stored print by Euclidean distance, a match under `MATCH_DIST` 0.5. `recogSee()` (called from `onFace()`) looks once a second until sure: one look under `SURE_DIST` 0.38 or 2 of the last 3 agreeing → `recogDecide(id)`; 2 of 3 unmatched → unknown (`id` null). Then it rechecks every 30 s (unknown: 5 s; no clear face: backs off to 8 s). `recogReset()` when no face for 3 s (`FACE_GONE_MS`), so a new arrival is looked at afresh. `whoInView()` = a person, `{unknown: true}` or null (no face in 5 s, Follow faces off, or not decided). People `{id, name, me, samples: [[128 numbers]] (max 10), thumb (72 px JPEG), created, lastSeen}` live in `people` and IndexedDB (`winslowLog` v5, store `people`), max 30; `me` marks the one person who is his human. Face prints and thumbnails stay on the phone; the AI only gets `facePromptText()`, a FACES line with the name ("your human" / "someone your human introduced" / "a face you do not recognise"). Greeting (`greetFace(who)`): his human as "sir", others by name, unknown faces without a name. Voice or typed commands in `faceCommand()` (runs in `think()` after backup, before `memoryCommand()`, with or without a key): "remember my face (I'm Sean)", "remember this face (as Mum)", "remember Jack's face" → `startEnrol()` (switches Follow faces on if needed, sets `busy`, takes 5 looks at least 350 ms apart within 14 s, 3 will do, all within 0.5 of the first; the same name again adds prints; warns if the face looks like someone else he knows); with no name he asks (`pendingFace` `{need: "name"}`, 60 s, and `judgeHeard()` lets a one-word answer through). "This is Mum" / "meet Jack" only count with a face in view and are confirmed first ("Shall I remember this face as Mum, sir?", `need: "confirm"`); `nameFrom()` rejects non-names (`NOT_NAMES`, -ing words, more than 3 words). "Do you recognise me?" / "who am I?" / "who is this?" → `faceTest()` (a fresh look). "That's not Jack, it's Sam" learns the face in view as Sam. "Forget Jack's face" / "forget my face" / "forget all the faces"; "whose faces do you know?". Dashboard **People** tab (`renderPeople()`): thumbnail, prints, last seen, Rename, This is me / Not my human, Forget. Senses and Status tabs show who is in view and how many faces he knows. Logged as `saw` ("Recognised Sean", "A face I don't know is in view") and `memory` (learned, forgot, renamed). Not reliable enough to be a lock: a photo or a lookalike can fool it, so it must never authorise anything (including body movements later). Planned next: per-person form of address and memory tags, prints that improve over time, guest mode (no memories or journal read out to an unknown face).
- **Setup link:** settings → "Copy setup link" puts key, everyday and thinking model, voice, pitch, rate, camera and sleep setting in a `#setup=` URL hash (never sent to a server). Opening it on any origin (GitHub Pages, Live Server, a tunnel, a new phone) imports them and strips the hash. Each origin has separate localStorage, which is why settings seemed to "reset".
- **Memory:** everything lives in one object `brain`, saved to `localStorage` under `robotBrain.v2` (name, form of address `brain.address` (default "sir", set in settings as "How Winslow addresses me"), persona, memory facts, recent history, voice settings, API key). `CHARACTER_VERSION` (now 3 = Winslow): when a saved robot has an older value, name and persona are reset and memory and chat history are wiped; key, model and settings stay (Winslow's untouched 1.4/1.1 pitch/rate move to the new defaults). Backups are a downloaded JSON file without the key (see "Backup and restore").
- **Activity log:** `logEvent(type, text)` records `heard`, `said`, `saw`, `memory`, `state` and `error` events in IndexedDB (`winslowLog` / `events`, newest 500 kept; in-memory fallback). `scrub()` strips the API key from every entry. `getEvents()` reads newest first; `logListeners` get live events. `brain.usage` holds today's chats, AI replies and summed OpenRouter cost (`countChat()`, which also adds to the month's spend, section 19), plus `remarkCost`, `dreamCost`, `briefCost`. Further types: `search`, `remark`, `mood`, `timer`, `skill` (v6.8), `model` and `diag` (v6.9), `ignored`. Note for headless testing: IndexedDB cursors (`getEvents()`) and `getUserMedia`/`enumerateDevices` stall under Edge's `--virtual-time-budget` (v6.7 too), so stub `getEvents` there, and test the microphone and camera in real time instead (headless Edge with `--remote-debugging-port`, `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`, driven over the DevTools protocol).
- **Brain dashboard (section 10):** opened by voice. Offline phrases ("show me your brain", "open your dashboard", "show your logs", "what's in your memory", "status report") or the AI's `show_dashboard` action call `openDashboard(tab)`. A sheet slides up (`#dash`, z 60) and the face shrinks to the top-left corner (`body.dash-open #face`, scale .32, z 59), still blinking and talking; that corner is left uncovered, so tapping the little face still talks, and a mic button sits in the header. His words and captions go to the header (`#dashSay`). - **Skills (section 17, v6.8):** exact little tools, so he never guesses at sums, conversions, dates or weather. Stock lines in `poolLine()`; with a key, first/return/reminder remarks may be AI-written (`aiRemark()`, no search, 10 s timeout, max 3 attempts a day, cost in `usage.remarkCost`). Speech only if `speechUnlocked` (a tap this visit) and outside quiet hours (`brain.quietHours`, `quietFrom` 22:00, `quietTo` 07:00); otherwise `silentSay()` shows the words at the mouth. Each remark is logged as `remark` and added to history so a reply makes sense. The AI prompt asks for dated "remember" facts with real dates.

## Character: Winslow
A composed, butler-style assistant with dry wit: the brilliant AI aide (in the spirit of Jarvis) blended with the devoted butler (in the spirit of Alfred), but his own character. Formal British manners, warmth under the polish, never cruel. Addresses the human as "sir" (or `brain.address`). One to three short, measured sentences, no exclamation marks, no gushing. Given a task: "Right away, sir." / "Consider it done." / "Very good, sir." Notices when the human is tired or stressed and says so gently. Quirk: rates things out of ten, unprompted now and then, with great seriousness; offline scores run 3–10, mostly 6–8, and a ten is rare and remarked on. Bears his unbuilt body with dignified patience. Cool pale-blue resting eyes. Replaced Sprocket (an excitable pet robot) in v4.0. The full persona text is `DEFAULTS.persona` in index.html.

## Rules
- Never put the OpenRouter API key (or any secret) in the code. The repo is public. The key is entered in the in-app settings and stored only in the browser.
- Bump `APP_VERSION` in `index.html` (shown top-left on screen) with every change, so it's clear which build the phone has loaded. **Always set `version.json` (repo root, `{"version": "vX.Y"}`) to the same value in the same commit**: the app polls it and reloads itself when it is newer.
- Keep it a single self-contained `index.html` unless there's a strong reason to split.
- iPhone quirks: speech must start inside a tap/click handler (see `unlockSpeech()`); silent mode mutes browser speech; fixed-position overlays need explicit `z-index` so buttons stay tappable.
- Test locally with the Live Server extension (port 5500); test on the phone via VS Code port forwarding (public visibility).
