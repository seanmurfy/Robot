# Winslow robot project

Winslow is a DIY companion robot. Right now it is a single-page web app (`index.html`) that runs on a phone and acts as the robot's face and brain. Later it will run on a donor Android phone mounted as the head of a two-legged, wheel-footed balancing robot.

## Current state (Phase 1: phone brain, no hardware yet)
- One file: `index.html` (HTML + CSS + JS, no build step, no frameworks).
- Hosted on GitHub Pages from the `main` branch: https://seanmurfy.github.io/Robot/
- Tested on iPhone in Chrome (Safari speech recognition was blocked by iOS settings).

## What index.html does
- **UI (face-first, section 9):** only the eyes and mouth show. An invisible full-screen `#tap` layer (z-index 1, under every control): tap = `toggleMic()` (start/stop talking, runs inside the tap handler for iPhone); swipe up or tap the bottom 15% = slim `#dock` (keyboard → `#typebar`, camera → live preview, settings). Dock auto-hides after 5 s and when listening, speaking or getting sleepy (`hideDock()`). The old `#mic`, `#look`, `#gear` buttons are kept hidden because the logic drives them. Winslow's spoken words appear at his mouth (`#speech` in `#mouthBox`, `body.saying` hides the mouth bar): `speak()` calls `sayStart()`, which shows one sentence-sized chunk at a time (`chunkText()`), lighting each word as it is said via `onboundary` word events, or a time estimate (~12 chars/s × rate) when the browser sends none; `sayEnd()` holds the last chunk 1.6 s; `mouthSay()` shows a line with no speech. The top caption is for the human's words and status messages only. Captions (`show()`) fade out 4 s (longer for long text) after listening/thinking/speaking stops; full text, no -webkit-line-clamp (garbles on iPhone). With the camera open, a photo is only sent for the first message, `LOOK_RE`/`VISUAL_RE` words, or Snap, to stop Winslow re-describing the same scene. Version + sleep timer live in settings; "Show debug info" (`brain.debug`) also shows them bottom-left. First-run hint once (`brain.hintShown`). Icons are inline SVG, 48px tap targets. z-index: tap 1, face 2 (59 while the dashboard is open), z's 5, captions/hint 6, debug 10, preview 20, dock/typebar 30, dashboard 60, settings 100.
- **Face:** animated pale-blue eyes (`--eye`) that blink and make small, slow glances; the listening glow is orange (`--listen`) so it stays distinct. Expressions are deliberately subtle (happy = soft eyes with a lifted lower lid, excited = slight brightening + one small nod, surprised = a raised eyebrow); emotions `happy`, `excited`, `sad`, `surprised`, `thinking`, `sleepy`, `neutral` (plus internal `asleep`) set via `setMood()` as CSS classes on `<body>`.
- **Sound:** `chirp()` plays one soft, low sine tone (signature sound), only when the mood changes to excited, on waking and when greeting a newly seen face.
- **Voice out:** browser `speechSynthesis`; voice, pitch (default 0.9) and rate (default 1.0) are user-selectable in settings. "Automatic" voice prefers en-GB, then en-US. Voices load a moment after the page does, so `speak()` waits (up to 1.5 s, polling `getVoices()`) before the first line; otherwise the first sentence after a reload came out in the default voice.
- **Ears:** `webkitSpeechRecognition` (tap the face) plus a typed-text fallback (dock keyboard). Conversation mode (`brain.convo`, on by default): after one face tap, `continueConvo()` restarts listening each time Winslow finishes speaking a reply; sends after a 1.3 s pause in speech (own timer, not the browser's), ends after one silent round (6 s with no speech), a second face tap, or if the browser refuses a non-tap restart. Each listen is capped at 15 s, and the mic is released when the page is hidden/closed (`releaseMic()`).
- **Brain:** `think()` calls OpenRouter (`https://openrouter.ai/api/v1/chat/completions`) when an API key is set. The model must reply with JSON: `{"say", "emotion", "remember": [{text, category, date}], "used": [memory ids], "action", "dashboard_tab"}`; `doAction()` runs the action (only `show_dashboard` so far). An optional `"display": {"title", "text"}` (simple markdown) carries anything that doesn't work as speech (lists, steps, recipes, code, tables, numbers, links, >3 sentences): `say` is just the gist + "it's on screen", and the dashboard opens on its **Notes** tab. `displayFrom()` also catches a `say` that is plainly unspeakable (list/code/table markup or >450 chars) and moves it on screen. Notes are kept in `brain.notes` (last 20, with search links), rendered by `mdHtml()` (escaped first, safe subset) with a Copy button; history keeps a shortened copy so follow-ups work. `max_tokens` is 1000 for this. Requests send `usage: {include: true}` so OpenRouter reports each reply's cost. With no key, `localBrain()` answers with offline regex rules.
- **Current facts:** every request's system prompt carries the local date, weekday, time and timezone (`nowText()`), plus `brain.homeCity` ("Home city" setting, optional). "Web search" setting (`brain.webSearch`, on by default; needs a key) adds OpenRouter's server tool `tools: [{type: "openrouter:web_search", parameters: searchParams()}]` = `{engine, max_results: 3, max_uses: 1}` ("Search engine" setting `brain.searchEngine`: perplexity (default), auto, exa). One search per reply; only if it finds no sources does `think()` send one retry with a "rephrase" nudge, and if that is empty too Winslow says he couldn't confirm it (never answers from memory). The prompt asks for self-contained queries (names instead of "they"/"it", month and year for schedules). The last successful search (sources with excerpts, query, answer) is kept in memory for 10 minutes (`lastSearch`, `recentSearchText()`) and put in the prompt so follow-ups answer from it without searching. Search cost today (`usage.searches`, `usage.searchCost`) uses `usage.cost_details.server_tool_cost` if reported, else the engine's list price (`SEARCH_PRICE`), shown on the Status tab. (The `web` plugin and `:online` suffix are deprecated; don't use them.) Search runs inside OpenRouter in the same request. The prompt tells the model to search anything time-sensitive and never guess; with search off or failed it must say it can't confirm. If the tool request fails (not auth/credit/rate errors), `think()` retries once without tools using `systemPrompt(true)`, and sets `searchBroken` for the session when the model can't use tools. While a search may be running: thinking face + "Consulting the wires…" (at once for `TIMELY_RE` questions, else after 2.5 s). `searchInfo()` reads `url_citation` annotations and `usage.server_tool_use_details` defensively (the docs only show the Responses API); each search is logged as a `search` event with sources as `links`, shown as tappable links in the dashboard log, never spoken. `parseReply()` tries every balanced `{...}` until one has `say`; `cleanSay()` strips URLs, links, citation marks and markdown from speech; history stores only the clean reply. Questions matching `MUST_SEARCH_RE` (scores, weather, news, prices, opening hours, next game…) and phrased as a question (`ASKING_RE`) must be backed by a search: if the model answers without searching, `think()` asks once more insisting on a search; if still none ran (or search is off/unavailable), the answer is replaced with "I can't confirm that at present" (skipped while the 10-minute `lastSearch` cache is fresh). Every request's system prompt ends with an EYES line saying whether a photo is attached; with none, he must not describe the human or the room and should suggest "look at me". Before sending a photo, `modelSees()` checks OpenRouter's public model list (`input_modalities`, cached per visit; unknown models allowed) and, for a model that can't take images, Winslow says so instead of sending. Offline: date questions answered locally; scores, news, prices etc. get "I'm afraid I can't confirm that at present".
- **Vision:** 👁 button opens a live camera preview (`openPreview()`); a `LOOK_RE` phrase ("what do you see", "look at this", "what do I look like", "how do I look", "what am I wearing") opens it too and snaps right away. While open, anything said or typed goes to `think()` with the current frame (`grabFrame()`: max 512px, JPEG q0.7, sent as an `image_url` part); The preview is a "daydream" thought bubble in the top right, 16px inside the safe areas (`#pvBubble` > `#pvClip` blob shape with feathered edges, slow morph and drift, `#pvTail` dots trailing toward the face; size `--pvw`). The picture itself is the shutter: tapping `#pvClip` (`snapFromBubble()`) sends "What do you see?" with a ring pulse (`#pvRing`) and a small dip (`#preview.snap`); while any photo is being sent, `#preview.sending` dims it and taps are ignored until the reply. The thought-trail dots below its lower-left are the controls (siblings of the shutter, so they never snap; round 48px tap targets ~50px apart, faint engraved marks): biggest dot ✕ `#pvClose`, middle dot flip `#flip` (when `enumerateDevices()` finds only one camera, `updateFlipDot()` → `setSolo(true)` makes it a plain, disabled dot), smallest dot decorative. Closing plays `#preview.closing` (the bubble shrinks back into the trail) before hiding. A faint "Tap to snap" shows under it for the first three opens (`brain.snapHints`). The eyes glance up-right at it (`lookAt(6, -5)`); in portrait the face re-centres below the bubble, in landscape to its left, and the top caption moves left of it. Camera choice is `brain.camera` ("user"/"environment"), set in settings or with the flip dot, falling back to any camera if the chosen one is missing. ✕, 60 s of no activity, or hiding the page closes the preview and stops all tracks. Needs an API key and a vision-capable model. Images are never stored; history gets a text note "[showed Winslow a photo]".
- **Sleep cycle:** after `brain.sleepAfter` idle minutes (setting: Never/2/5/10, default 2) Winslow yawns and goes `sleepy`; 3 minutes later `asleep` (breathing line eyes, floating z's in a `pointer-events: none` layer). Never sleeps while listening, thinking, speaking, settings open, or camera preview open. Any tap/key wakes him (`wake()`), unhurried: half-open sleepy eyes, then they open smoothly (`body.waking` slow transitions) with a soft tone, then a composed wake line ("Ah. You're back, sir."). The waking tap is swallowed so it doesn't also press a button; a typed message sent while asleep is answered after the wake line.
- **Face tracking (section 8):** "Follow faces" setting (`brain.followFaces`, off by default, not carried by backups or setup links). MediaPipe Tasks Vision `FaceDetector` (BlazeFace short range, VIDEO mode) from jsDelivr `@mediapipe/tasks-vision@0.10.14`, model from Google's mediapipe-models bucket. Hidden 320x240 front-camera stream, ~10 detections/s; when the live preview is open it detects on the preview's video instead (only one stream ever: `startCamera()` stops the tracking stream, `closePreview()` restarts it). Eyes glide (20%/frame) toward the biggest face, x mirrored, clamped to the glance range; eyes keep looking at the preview while it's open. New face after 10+ s → happy look, soft tone + "Good evening, sir." caption by time of day (no speech). No face for 30 s → random glancing again. Faces count as activity (`poke()`); while sleepy/asleep the eyes don't follow and detection slows to 1/s just to wake Winslow when a face appears. Paused while the tab is hidden and during snapshots. Model or camera failure turns the setting off with a caption.
- **Setup link:** settings → "Copy setup link" puts key, model, voice, pitch, rate, camera and sleep setting in a `#setup=` URL hash (never sent to a server). Opening it on any origin (GitHub Pages, Live Server, a tunnel, a new phone) imports them and strips the hash. Each origin has separate localStorage, which is why settings seemed to "reset".
- **Memory:** everything lives in one object `brain`, saved to `localStorage` under `robotBrain.v2` (name, form of address `brain.address` (default "sir", set in settings as "How Winslow addresses me"), persona, memory facts, recent history, voice settings, API key). `CHARACTER_VERSION` (now 3 = Winslow): when a saved robot has an older value, name and persona are reset and memory and chat history are wiped; key, model and settings stay (Winslow's untouched 1.4/1.1 pitch/rate move to the new defaults). Backup/restore copies JSON without the key.
- **Activity log:** `logEvent(type, text)` records `heard`, `said`, `saw`, `memory`, `state` and `error` events in IndexedDB (`winslowLog` / `events`, newest 500 kept; in-memory fallback). `scrub()` strips the API key from every entry. `getEvents()` reads newest first; `logListeners` get live events. `brain.usage` holds today's chats, AI replies and summed OpenRouter cost (`countChat()`).
- **Brain dashboard (section 10):** opened by voice. Offline phrases ("show me your brain", "open your dashboard", "show your logs", "what's in your memory", "status report") or the AI's `show_dashboard` action call `openDashboard(tab)`. A sheet slides up (`#dash`, z 60) and the face shrinks to the top-left corner (`body.dash-open #face`, scale .32, z 59), still blinking and talking; that corner is left uncovered, so tapping the little face still talks, and a mic button sits in the header. His words and captions go to the header (`#dashSay`). Tabs: **Notes** (what he put on screen, newest first; "show me that again" opens it), **Logs** (filter chips, live), **Memory** (grouped by category; edit text, kind, date and importance, delete, add form with a kind picker), **Journal** (diary entries, newest first), **Senses** (live camera: reuses the bubble's or face tracking's stream, otherwise opens `sensesStream` just for the tab and stops it when the tab closes; face detected, mic, body readings "not connected yet"), **Status** (version, model, key shown only as set/not set, chats and cost today, sleep state, body connection). While open, `dashCommand()` handles commands before the AI: switch tabs, "scroll down/up", "forget that last one", and closing ("close the dashboard", "that'll be all", "thank you Winslow"). The X button, a swipe down (header, grip, tabs, or the list when at the top) or Escape close it too. It blocks sleep (`sleepBlocked()`).

- **Long-term memory (section 1, "Long-term memory"):** `brain.memory` is a list of entries `{ id, text, category, date, importance (1-5), created, lastUsed }`; categories `MEM_CATS`: person, preference, routine, plan, promise, joke (running joke), fact. `date` is "YYYY-MM-DD" or "MM-DD" (yearly); without one, dates written in the text count (`memDueIn()` = days until due). `normalizeMemory()` runs on load, restore and migrates old plain strings to "fact". `rememberFact()` takes a string or object and de-duplicates by text. Each request sends `relevantMemories()` (25: plans/promises due within 7 days first, then `memScore()` = importance + recency of last use), as `[id] kind, due: text` lines; the prompt tells the model how to use plans, promises, routines and running jokes sparingly and to list the ids it drew on in `"used"` (`markUsed()` sets `lastUsed`). Voice, with or without the AI (`memoryCommand()`, runs first in `think()`): "forget that" deletes the newest entry and says which; "read me yesterday's journal" (also today, a weekday, "N days ago", a date, or the latest) reads an entry aloud (`speak(..., { long: true })`). The settings Memory box keeps unchanged lines' entries; new lines become facts.
- **Dreaming (section 12):** once per calendar day, only with an API key (`dreamDue()`), on first open of the day or when idle (`dreamIdle()`: within 20 s of opening, drowsy/asleep, or 5 untouched minutes). Skipped free of charge if nothing was said and no memory was added since the last dream. `dream()` sends every memory plus the log since the last dream (`brain.dream.at`) and gets back operations `{merge, drop, update, add, journal}` applied by `applyDream()` (untouched entries are never rewritten; a dream asking to drop more than half is ignored; then trimmed to `MEM_MAX` 80). Face: `showDreamFace()` = closed "asleep" eyes + caption "Winslow is dreaming…"; any touch, key or word brings the face back while the request finishes in the background. Failures leave memory alone, retry after 30 min, max 2 tries a day. Cost in `usage.dreamCost`. Remarks wait for a dream to finish.
- **Journal:** the dream's `journal` (3 to 5 sentences in Winslow's voice, with an out-of-ten rating) is stored per day in IndexedDB (`winslowLog` v2, store `journal`, key "YYYY-MM-DD") and mirrored in the `journal` array (newest first). The entry is dated by the last thing the human said before the dream, so a first-open dream writes up yesterday. Dashboard **Journal** tab; backups include `journal` and structured memory, never the key.
- **Mood (section 11):** `brain.feel` holds two slow values, spirits and energy (-1..1), nudged by `nudgeMood(ds, de, why, quiet)`: kind words/thanks +0.15, harsh words aimed at Winslow (`HARSH_RE`) -0.2, each reply +0.02 (+0.05 with a display/action), brain error -0.08, camera fault -0.04, being left alone 3+ daytime hours (10 pm–7 am not counted) down to -0.25, a full sleep +0.08 energy. Nudges decay toward 0 (half-life 2 h, `feelStored()`); effective energy adds the clock (`clockEnergy()`, low in the small hours) and session length (`sessionEnergy()`, after the first hour present). `moodPrompt()` puts one line in every system prompt ("tone only very slightly"). The resting face shades with it via CSS vars on `<html>`: `--eye-h` (up to 12% less open when tired) and `--glow` alpha (.32–.48 with spirits). `moodCheck()` (every 30 s) logs a `mood` event when the wording changes; notable nudges log too. Shown on the Status tab.
- **Speaking first (section 11):** triggers: first presence of the day (greeting by time of day), back after 2+ h (welcome back), present 2+ h straight (stretch / eat / rest by hour), after midnight (once a night), a memory fact containing today's date (`factDueToday()`: "14 November 2026", "3 March" = yearly, "November 14th", ISO). Presence = face seen, touch, key, talking, or opening the app (`notePresence()`; `brain.pro.seenAt/presentSince`). Greetings are queued (`pendingRemark`, dropped after 3 min or once the human starts talking); if Winslow is asleep, a queued greeting becomes the wake-up line. Setting "Speaks first" (`brain.proactive`: off / rarely = 3 a day, 2 h apart / sometimes = 6 a day, 45 min apart; default rarely). `remarkBlocked()`: never while listening, convo, thinking, speaking, typing, settings, camera, dashboard, asleep, within 30 s of speech or 2 min of the human talking. Stock lines in `poolLine()`; with a key, first/return/reminder remarks may be AI-written (`aiRemark()`, no search, 10 s timeout, max 3 attempts a day, cost in `usage.remarkCost`). Speech only if `speechUnlocked` (a tap this visit) and outside quiet hours (`brain.quietHours`, `quietFrom` 22:00, `quietTo` 07:00); otherwise `silentSay()` shows the words at the mouth. Each remark is logged as `remark` and added to history so a reply makes sense. The AI prompt asks for dated "remember" facts with real dates.

## Character: Winslow
A composed, butler-style assistant with dry wit: the brilliant AI aide (in the spirit of Jarvis) blended with the devoted butler (in the spirit of Alfred), but his own character. Formal British manners, warmth under the polish, never cruel. Addresses the human as "sir" (or `brain.address`). One to three short, measured sentences, no exclamation marks, no gushing. Given a task: "Right away, sir." / "Consider it done." / "Very good, sir." Notices when the human is tired or stressed and says so gently. Quirk: rates things out of ten, unprompted now and then, with great seriousness; offline scores run 3–10, mostly 6–8, and a ten is rare and remarked on. Bears his unbuilt body with dignified patience. Cool pale-blue resting eyes. Replaced Sprocket (an excitable pet robot) in v4.0. The full persona text is `DEFAULTS.persona` in index.html.

## Rules
- Never put the OpenRouter API key (or any secret) in the code. The repo is public. The key is entered in the in-app settings and stored only in the browser.
- Bump `APP_VERSION` in `index.html` (shown top-left on screen) with every change, so it's clear which build the phone has loaded.
- Keep it a single self-contained `index.html` unless there's a strong reason to split.
- iPhone quirks: speech must start inside a tap/click handler (see `unlockSpeech()`); silent mode mutes browser speech; fixed-position overlays need explicit `z-index` so buttons stay tappable.
- Test locally with the Live Server extension (port 5500); test on the phone via VS Code port forwarding (public visibility).

## Roadmap
1. Phone brain (now): face, voice, AI, memory, camera snapshot + vision ("what do you see?").
2. Balancing base: ESP32-S3, 2x 2804 gimbal motors with SimpleFOC, BNO085 IMU, LQR balance.
3. Leg height: 2x Feetech STS3215 servos, linkage legs.
4. Head + link: pan/tilt neck, phone cradle, phone to ESP32 over USB serial (newline-delimited JSON commands like `{"cmd":"drive","v":0.3,"turn":0}`).
5. Claw arm: 3 small bus servos, vision-guided grab.
6. Learned skills: MuJoCo sim + RL (jumping, fall recovery).

Hardware commands from the AI become tool calls (`drive`, `look`, `set_height`, `grab`, `emote`, `remember`). Firmware enforces all safety limits; the AI never controls raw motor power.
